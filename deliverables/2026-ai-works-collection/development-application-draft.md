## 第一部分｜作品基本信息

<!-- basic-info-start -->
**作品名称：** 学途智伴——从一道错题，到一周学习建议。

**作品类型：** AI 智能体，以网页工作台提供服务。

**应用场景：** 面向初中数学学习，帮助学生整理试卷和作业中的错题。目前围绕八年级下册的二次根式、一次函数开展验证。

**主要功能与创新点：** 作品将练习图片识别、学生确认、错因分析、学习记忆和周报串成一条流程。它不只记录“哪道题错了”，还尝试结合具体作答解释问题，并比较多次练习中的重复错误与局部变化。AI 提出的学习记忆由学生决定是否保留；缺少解题过程时，不强行猜测错因。周报把分散记录整理成有题目依据的复习重点和少量行动建议。作品复用成熟 OCR 与大模型服务，将自主设计重点放在分析方法、证据关联和人机协作上。
<!-- basic-info-end -->

### 为什么做这个作品

进入初中后，试卷、错题和学习备注越来越多。做完一道错题，并不容易看清同类问题是否再次出现，也不容易发现自己在哪一步有了进步。因此，这个作品尝试让 AI 比较多次作答，同时让学生保留关键判断权。

**核心想法：它不是替我学习，而是帮我把问题看清楚。**

图 1：系统架构与学习智能体工作流程。教材知识底图先在线下整理并人工核对，线上不处理教材 PDF。`/demo` 为预置演示，`/app` 为真实工作台，两者数据与执行路径分开。

### 组件部署在哪里，怎样相互调用

系统分为三个位置：学生设备上的浏览器、项目自己的腾讯云 VPS，以及外部 OCR 和大模型服务。VPS 是租用的云服务器，部署了网页服务、应用后端、Hermes 和数据存储；DeepSeek 模型本身不部署在这台 VPS 上。

| 能力或组件 | 部署／运行位置 | 谁调用它、通过什么接口 | 职责与交换的内容 |
| --- | --- | --- | --- |
| Web 工作台 | 学生设备的浏览器；页面由 VPS 提供 | 学生操作页面，页面向后端发送 HTTP API 请求 | 上传图片、确认错题、查看任务和分析结果；不直接调用云端模型 |
| Nginx 网关 | 项目 VPS | 接收浏览器请求，提供网页并转发 API 请求 | 提供统一访问入口，分别承接演示和真实应用 |
| Express 应用后端 | 项目 VPS | 接收网页请求，分别调用 OCR、Hermes 和存储 | 组织任务、准备输入、检查输出、保存结果并返回页面 |
| 腾讯云 `QuestionSplitOCR` | 外部腾讯云 OCR 服务 | 后端通过腾讯云 SDK 调用云 API | 接收练习图片，返回题目区域及识别文字；不是 Hermes 内部的识图步骤 |
| Hermes Agent | 项目 VPS 上的本地程序 | 后端通过本地进程启动命令行任务，传入结构化数据并接收结果 | 加载指定 skill，结合本次材料组织模型任务；无需学生打开 Hermes 界面 |
| 项目自定义 skills | 版本化文件随项目部署到 VPS | 后端选择任务对应的 skill，由 Hermes 加载 | 保存分析步骤、判断边界和输出要求；不是另一个云服务 |
| DeepSeek 大模型 | 外部模型服务 | Hermes 通过配置的模型 API 调用 | 根据 skill 和任务材料完成理解、推理与生成；应用后端不直接调用它 |
| SQLite 与私有文件 | 项目 VPS | 应用在本机读写；不开放给浏览器或模型直接操作 | 保存题目、分析结果、记忆决定与报告，供后续任务按需取用 |

一次真实任务中，浏览器先把练习交给后端，后端调用 OCR，再将识别结果交学生确认。确认后，后端选择相关题目、教材知识和已接受记忆，连同指定 skill 交给 Hermes。Hermes 调用 DeepSeek 生成分析，应用检查结果后保存并展示。这里的“本地 Hermes”是相对 VPS 而言，不是运行在学生电脑上；模型推理仍通过网络完成。

### Hermes 的核心价值：把验证过的经验固化为 Skills

本项目使用 Hermes 的重点，不只是“替应用调用一次大模型”，而是把学习分析中逐步积累的经验整理为可复用、可检查、可修改的 skills。模型提供通用理解和推理能力，skill 则说明：在这个学习场景里，应当怎样使用这些能力。

一份 skill 可以理解为“分析方法手册”：需要哪些材料，先检查什么，怎样对照题目与学生作答，什么证据足以支持判断，什么时候应保留未知，以及怎样给出学生看得懂的结果。它主要以文字组织方法和要求，不是把每道题的答案写成固定程序，也不是重新训练模型权重。程序仍需检查格式与来源，开发者仍需检查数学和内容质量，不能只靠 skill 保证正确。

例如，试验发现模型可能根据一个错误答案补想学生未写出的步骤。值得沉淀的经验不是“记住这道题应该答什么”，而是更通用的方法：**先区分可见作答与推测；只有答案时，不把某条可能的错误过程当成事实。**再如，学生这次正确求出了 b，却在后面算错，分析就应保留做对的部分，而不是沿用旧记忆笼统地说“仍然不会求 b”。

这些经验写入 skill 后，后续任务可以沿用同一套分析方法，不必每次聊天重新解释。它们保存在项目文件中，开发者能够阅读、比较版本、修改和回退。更换模型时，这些方法仍可作为起点，但必须重新验证效果，不能假定表现不变。

### 经验怎样产生：运行、检查、修订、再验证

经验不是让模型写出一份长提示词就自动获得，而是在有反馈的迭代中形成：

```text
代表性案例 → 运行当前 Skill → 核对实际结果 → 提炼通用经验
     ↑                                      ↓
     └──── 用旧案例和新变体复验 ← 修订 Skill ────┘
                       ↓
             有改善才采用新版本，否则保留或回退
```

这个闭环中，先检查问题来自哪里：图片识别错了，就处理输入；题目与历史记录对应错了，就修正应用；分析方法有问题，才修改 skill。不能把所有问题都变成新增提示词。复验既看原来的问题是否改善，也看其他题目是否出现退步，保留失败记录，不把一次好答案当成稳定能力。

**可持续积累的成果，是分析方法、代表性案例和验证记录，而不只是某次生成的漂亮答案。**目前由开发者在 AI 辅助下完成这套迭代，再把选定的 skill 版本交给应用使用；不是每次学生使用后，智能体都会自动改写自己的技能。

这里还要区分两种积累：**skills 保存“怎样分析”的通用方法，学生记忆保存“这个学生此前出现过什么”的个体线索。**前者经过开发验证更新，后者经过学生接受后由应用保存。题目变多会增加可比较的证据，但不等于 skill 或模型已经自动学会了更好的方法。

上述是开发质量的反馈闭环。学生收到建议后，是否练习、是否有效、如何再调整，是另一条学习反馈闭环；当前提供建议和后续作答比较，尚未实现完整的行动执行与效果跟踪。

### 两个核心技能

**错题分析技能：看清这一次。** 读取已确认错题的题干、学生作答和相关知识，生成有依据的学习发现、建议以及可选的记忆候选。先看实际步骤，不因为学生选了错题就编造错误原因。

**周报生成技能：联系多次练习。** 综合本周学习发现及其原始作答，参考必要的已接受记忆，区分重复问题、局部变化和原因未知，给出少量优先行动。单次答对某一步，不等于整个知识点已经掌握。

## 第三部分｜开发过程与关键改进

### 从想法到可用流程

```text
发现学习中的问题 → 说清需求并拆成小任务 → 与 AI 讨论设计
       → AI 辅助编码与测试 → 人工运行、核对结果 → 修改并继续验证
```

开发先从一条完整使用路径出发：学生上传练习、确认错题、阅读分析，再查看周报。围绕这条路径分别实现网页、数据保存和 AI 服务连接，用少量代表性题目检查每一步，最后再把它们串起来。

早期先用 Demo 和预置样例验证功能流程与交互，再逐步接入真实服务，避免在需求尚未清楚时就投入复杂部署和付费调用；接入后仍保留 Demo，方便稳定展示与比较。

### 设计中做出的三个选择

**先做什么：把精力放在学习分析上。** 图片识别交给成熟的 OCR 服务，教材知识先离线整理，只选择数学中的两个章节作为起点。学生确认错题后，系统再分析作答。这样既控制开发规模，也不要求 AI 一次包办教材处理、识别和判卷。

**记住什么：保存线索，不给学生贴标签。** 例如，一道题漏求一次函数中的 b，能说明这次步骤不完整，却不能直接说明学生一直不理解截距。系统把可能值得关注的内容列为记忆候选，由学生决定是否保留；以后再遇到相关题目，仍要以新的作答为准。

**怎样看变化：让周报回到题目本身。** 只统计“二次根式错误两次”，还不足以说明两次错在同一处。周报同时读取分析记录和原始作答，比较具体步骤，再决定是不是重复问题、哪一步有变化。学生不需要先接受每条分析为记忆，才能把它纳入本周报告。

### 一次真实的试验与反思

单题试验曾比较同一道题的两种输入：一种保留错误步骤，另一种只给最终答案。有步骤时，可以指出错误发生在哪里；只有答案时，模型却可能补想学生没有写出的过程。试验也发现，增加分析规则虽然能改善某些表述，却可能引出新的数学或证据问题。

因此，项目没有把“规则越多、解释越长”当成进步。没有明显收益的候选修改没有采用，失败输出也保留。单题目标收敛为解释本题、指出可见问题、保留不确定性；更深入的共性判断交给后续多次练习比较。随后用 A/B 两批材料检验重复问题、局部变化和原因未知，而不是只展示一道表现最好的题。

检查时不仅看程序有没有成功返回，还要核对数学是否正确、结论有没有作答依据、建议能不能执行。小样本能帮助发现问题，但不能用来宣称系统整体准确率。

### 怎样使用 AI 辅助开发

项目采用 AI 辅助开发：用编程助手帮助理解代码、实现功能、排查问题和整理测试；由人确定目标、检查结果并决定是否采用修改。系统中的学习分析 AI 与开发时使用的编程助手，是两种不同用途。

## 第四部分｜如何打开和使用

**运行方式：** 网页应用，使用者通过浏览器打开，无需在个人电脑上安装 Hermes 或配置模型密钥。作品提供两条体验路径，下文的 `/demo` 和 `/app` 均指作品入口下的相对路径。

### 先选择体验路径

**Demo 路径（`/demo`）：先了解完整流程。** 使用预置样例，体验材料导入、错题确认、学习分析、记忆确认和周报查看等环节。无需接入 OCR、模型密钥或真实分析后端，适合快速了解作品，也便于开发早期检查页面衔接和功能流程。演示中的操作和输出基于样例，不会调用真实 OCR 或大模型，也不会写入真实应用的学习记录。

**真实应用路径（`/app`）：处理实际学习材料。** 上传练习图片后，由后端调用 OCR，经过人工确认，再调用 Hermes／DeepSeek 完成分析与周报，保存结果及学生的记忆决定。它依赖服务器与外部服务正常运行，生成过程需要等待，结果也需要核对。

两条路径服务于不同的验证目标：**Demo 验证和展示功能流程，不证明识别准确性或模型分析质量；真实路径还需要检验实际调用、生成结果和数据保存。**真实调用失败时，不把预置演示结果冒充为本次生成结果。

### 真实工作台的使用步骤

1. **打开工作台。** 访问 `http://49.233.203.222/apps/xuetuzhiban/app/overview`，进入真实应用。公开演示只用于浏览预置流程，不会执行真实 OCR 或推理。
2. **上传练习图片。** 准备清晰、方向正确的 JPG/PNG 图片，包含题目和学生作答。已有上传实现的单张原图上限为 7 MiB。不要上传姓名、学校、班级等无关个人信息。
3. **确认题目。** 查看切题和识别结果，勾选需要分析的错题，核对作答；对于没有识别出答案的题目，按页面提示补充。若已有识别内容错误，应先核对原图，不把错误文本当作可靠输入。
4. **查看分析并决定记忆。** 启动分析后等待任务完成，阅读具体依据和建议；对记忆候选选择接受或忽略。
5. **积累记录并生成周报。** 完成后续练习后，手工触发本周报告，查看重点与行动建议。仅有本周错题材料时，不把结果当作整卷正确率或总体成绩趋势。

## 第五部分｜应用案例、验证与反思

### 沿用 A/B 两批练习，讲清一个完整故事

材料是两批原创仿真数学练习，每批 10 题、约 3 道重点错题。它们用于检查系统的工作方式，不是真实学生长期成绩记录。

| 观察对象 | 题目与作答证据 | 已有结果体现的帮助 |
| --- | --- | --- |
| 重复问题 | A06 将 √18＋√8 写为 √26；B06 将 √27＋√12 写为 √39 | 联系两次具体作答，指出直接相加被开方数的问题；建议先化简、再合并同类根式，并重做两题 |
| 局部变化 | A10 漏求一次函数中的 b；B10 已正确求得 b＝3，但后续计算仍出错 | 认可求 b 这一步的变化，同时指出新的计算错误，不把局部变化夸成整体掌握 |
| 原因未知 | B09 只有最终答案，没有解题过程 | 区分“答案错误”与“知道为什么错”，不沿用别题的错因猜测本题 |

表中是已有分析结果的概括，不是模型逐字原文。学生可以据此先重做 A06、B06，练习“化简后再合并”，然后在新的练习中检查是否还出现相同问题。系统目前提供建议，并未自动跟踪建议是否执行，也不能据后续某题的变化认定建议已经奏效。

### 验证说明

验证分为两部分：一部分用练习图片检查 OCR、确认和分析的连接；另一部分用已核对的 A/B 仿真文字，检查真实 Hermes 分析、记忆复用和周报。当前工作台可查看已保存的 A/B 结果；新截图须标明是当前界面呈现的既有结果，不是两张 A/B 图片重新上传后的完整实录。原始输出和检查记录保留，便于追溯。

### 局限与下一步

识别和模型分析都可能出错，缺少解题过程时尤其难以判断原因。当前验证集中在初中数学的少量代表性材料，尚不能证明长期提分效果。下一步重点是把建议真正用于复习，再收集后续作答反馈，检查哪些帮助有效；同时逐步扩大知识范围。
