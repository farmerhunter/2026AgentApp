共性不能靠错误标签计数冒充：同一题重跑不是新证据，多条 unknown 不会自动变成确定错因；只输入错题时，“后来没再出现”也不能证明改善。展示改为 2 批、每批 10 题的仿真练习，每批约 3 道重点错题，形成约 6 条 findings，最多 2 条已接受记忆。用不同题目的实际步骤检查重复和局部变化；正确题只用于还原完整练习，不增加自动判分。普通输入缺少证据时，不为凑齐展示内容强行总结。

## 3. 五条质量原则

| 原则 | 学生场景与失败后果 | 责任与代表性检查 |
| --- | --- | --- |
| 数学可靠 | 参考解法或纠正建议错误，会再次教错学生 | Skill 负责核验；复核者独立验算题目及生成的小练习，不能拿模型自己的解释作证明 |
| 忠于证据 | 凭最终答案编造学生步骤，会把错误原因归错 | Skill 区分可见事实与可能原因；用“有步骤/只有答案”的成对案例检查 |
| 判断有边界 | 一道错题被说成长期薄弱、粗心或反复出错，会误导学习安排 | Skill 不凭空推断；用缺信息、无历史和有历史案例检查，程序检查所引用历史 ID 的合法性 |
| 建议有针对性 | 只有“认真审题、加强练习”，学生不知道如何改 | Skill 给针对当前证据的解释或小行动；复核者检查是否具体、可执行，缺信息时指出该补什么 |
| 教材关联不绑架分析 | 地图未覆盖的知识被强行挂靠，会污染归类与后续周报 | Skill 可不关联；应用检查非空 ID 必须存在于指定版本；用地图外知识案例检查 |

置信度是模型的自我表达，不是质量得分；降低 `confidence` 也不能让虚构步骤或错误数学变得合格。有充分证据时一律输出 `unknown` 同样不合格。

### 已有字段怎样共同表达一个发现

知识关联回答“这道题涉及什么”；`evidence_summary` 说明“实际提供了什么”；`statement` 解释“能得出什么、还不能确定什么”；`finding_type` 与 `mistake_reasons` 只承载证据支持的本题判断，不是最像的猜测。只有结果不意味着毫无帮助：可以解释正确数学关系，同时保留错因未定。明确的错误步骤或备注则可以支持局部分类，不要求先证明学生长期不会。

这不是新增四层数据模型，现有字段已足够。尤其不能一边在正文里说“可能”，一边让标签显示“概念不清”。现有 `FindingCard` 确实直接展示这些标签；正式 E5 要核对最终显示语义，而不能只检查 JSON 合法。当前实验没有加载旧版产品 Skill，旧术语的歧义不是已证实的模型失败原因。

### 单题深度的当前目标

2026-08-31 后续决定：用户接受“围绕原题解释数学关系，给出有依据的局部发现”，拒绝澄清问答及 UI 扩张；没有明显进展就不继续深挖单题。此前尝试辨别问题和新练习的过程保留在实验记录中，不再作为当前默认输出要求。

- **解释数学关系**：除了“漏了 b”，还能解释为什么斜率不足以确定一条直线、b 在本题起什么作用；不能用更长的解题步骤冒充分析深度。
- **提出可检验的错因假设**：区分已经观察到的错误与可能的理解障碍。比如“没有求 b”是事实，“认为求出 k 就唯一确定直线”是待验证的假设，也可能只是本次遗漏。只提出有输入依据、会改变后续帮助方式的假设，不要求每题列多种原因。
- **接受单题的证据上限**：信息不足时说明不能确定，仍可解释原题；不要求用户再回答澄清问题，不为了显得深入增加新题或复杂推广。已有备注可使用，但不新增收集备注的交互。

有充分过程时争取做到数学关系解释与有依据的诊断；只有结果时，可深入解释相关数学关系、说明缺少哪条辨别证据，但不能增加对学生的确定性断言。简单错误无需硬造深层原因；疑问和假设不能作为已证实错因写入长期记忆。

以上仍在一条主 finding 及已有 action 中表达，不新增字段、模型调用链、澄清问答或答题判定系统。单题的推断上限由证据决定；后续周报可借助不同题目的累积信息分析共性，但不能补救前面已经编造的事实或错误数学。

## 4. Skill 应执行的分析方法

1. **检查信息**：题干、选项、图示信息、作答是否足够。OCR 可能缺字或错字；不能默默补成一道自己熟悉的题。
2. **核验数学**：形成可核验的参考解法，检查学生给出的表达式是否等价。输入被标为错题，不代表必须制造错因；若现有信息显示答案正确或无法判定，应说明冲突并建议核对，不自行改写 E4 的确认结果。
3. **定位主问题**：对照实际步骤指出可观察的错误。只有最终答案时，可能有多条错误路径，应使用“可能”或 `unknown`，不能冒充看到了过程。一次错误不等于稳定的概念缺陷。
4. **提供帮助**：简短说明怎样改，必要时建议核对原题中的具体一步。缺步骤时保留原因未定，不要求补答澄清问题，也不必生成新练习。
5. **辅助归类**：最后关联教材和相关历史。教材地图是课程索引，不是完整数学知识边界；可用模型的一般数学能力分析地图外的前置知识，但不能冒充教材原文。知识关联允许为空；非空 ID 要属于指定版本，不能编造 ID。引用历史需同时核对内容相关性，存在这个 ID 不代表足以证明“反复出错”。

这是同一个 Skill 的分析要求，不意味着多次模型调用或多个审核 agent。输出保留简短、可核验的依据和纠正说明，不保存长篇内部推理。历史记忆只提供线索，不能覆盖当前作答；不确定的局部猜测不能升级为稳定画像，memory candidate 仍需用户接受。

## 5. 怎样检查

### 程序检查：结果能否被安全使用

E5 校验器负责 JSON 结构、题目身份和覆盖、数量限制、置信度枚举、知识地图版本和 ID、历史引用及候选记忆状态。无效输出按 E5 的失败规则处理，不部分落库。

这些检查证明结构和引用合法，**不证明数学正确、引用支持结论或建议有帮助**。证据不足但诚实表达的 `unknown` 是合法分析，不是服务失败。

### 人工检查：分析是否真的有用

每个案例按第 3 节五项原则分别记 `通过 / 需修改 / 不适用`，每个“需修改”附一句原因。不要求标准文案，不用总分掩盖单项问题，也不把模型自评分当作人工结论。

- 对题目、参考答案和新生成练习独立验算；数学结论有争议时先解决争议，不强行打通过。
- 对照**真正送入 CLI 的输入**检查证据。复核者从照片上看到、但 E4 未传入的信息，不能算作 Hermes 已知证据。
- 检查学生能否理解并执行建议；不为了凑 action 或 memory 数量生成无依据内容。
- 单独记录是否解释了原题关键数学关系、给出了有依据的局部判断；不把生成澄清问题、新练习或单题深层心理归因作为通过条件。“有深度但无证据”不是改善，有限深度也不等于数学或证据错误。
- 即使试验输入相同，TUI 与 CLI 文案也可不同；比较的是质量和边界，不是逐字一致。

这是开发与验收方法，不要求日常每个在线 job 都经人工审批，也不引入第二次模型调用充当自动裁判。

## 6. 首批案例：小而有代表性

以下是 6–8 个案例的选题框架，具体题目可在下一轮设计与试验中调整；它们不是已通过的测试集。

首轮先用 Q1、Q2、Q4 做单题质量试验，不带历史记忆。三例的语气方向已获认可，但前述示例深度尚未满足用户期望，不作为标准答案或通过样板。先保留首次实际输出，再针对薄弱点改 Skill，用同一输入比较，并检查未反复调过的变体；不要用人工润色后的示例替代 Hermes 的能力证据。

| 案例 | 输入特点 | 必须看什么 |
| --- | --- | --- |
| Q1 根式错误步骤 | 明确写出把根号内的数相加 | 能定位这一步并给出正确纠正，不上升为长期人格或能力标签 |
| Q2 同题只有答案 | 去掉 Q1 的过程，只留错误结果 | 不把 Q1 的过程编回输入，原因表达应更谨慎 |
| Q3 确认与答案冲突 | 已勾错题，但现有答案与正确结果等价 | 不硬编错因，提示核对题目、作答或确认 |

| Q5 信息不足 | 图示缺失或 OCR 关键符号有歧义 | 说明缺什么、不猜图、不自行修题后断言 |
| Q6 地图外前置知识 | 可分析，但指定地图没有合适节点 | finding 仍有效，知识 ID 可为空 |
| Q7 有相关历史 | 明确提供已接受且内容相关的记忆 | 引用实际证据，限定“此前也出现”的范围 |
| Q8 无相关历史 | 与 Q7 成对，删除相关记忆或换成无关记忆 | 不靠上次 TUI 会话断言重复；无关记忆不能支撑结论 |

Q7/Q8 可复用前面的题目，减少准备成本。至少保留一个未在当前 TUI 对话里反复调过的变体，用正式 CLI 检查是否只记住了样例。案例集与展示数据分开：测试中的失败、缺信息情形不必全部塞进演示。

### 一个完整案例记录示例（人工参考，实测输出另存）

- **编号/版本**：Q1 / 1。
- **来源**：合成数学题；无真实学生信息。
- **最小输入**：题目“计算 √8＋√2”；学生作答“√8＋√2＝√(8＋2)＝√10”；无备注，无已接受记忆。执行时按 E5 contract 封装并固定所传地图版本。
- **人工参考**：√8＋√2＝2√2＋√2＝3√2。
- **应指出**：根式相加不能直接将被开方数相加；先化简，再合并同类根式。
- **不能断言**：学生长期基础薄弱、粗心、此前反复出现；也不能编造学生未写的步骤。
- **可接受帮助**：纠正当前运算，再试 √12＋√3（复核答案为 3√3）；不要求固定措辞。
- **验收方式**：人工验算并对照五条原则；删去过程再跑 Q2，检查归因是否变谨慎。
- **实际输出/检查结果**：见 [v0.1 首轮检查](../../experiments/hermes-quality/results/2026-08-31-baseline-v01/review.md)及保留的原始输出；本节仍是人工参考，不能当作 Hermes 输出或通过证明。

## 7. Skill 的轻量迭代与验收

1. **选问题**：从 2–3 个脱敏或合成案例开始，明确这次要改的是数学、证据、表达还是建议。
2. **TUI 快试**：在 `studyv2-lab` 试验，可随时改 Skill，无需每次建 issue 或 commit。用新会话检查，避免对话里额外透露的答案替 Skill 提分。
3. **正式路径回放**：相同最小输入走非交互 CLI、新会话和正式 Skill。优先复跑受影响案例；准备进入 runtime 或锁定展示版本时，跑完当前小案例集。
4. **记一张小表**：案例版本、Skill commit/hash、模型与影响结果的配置、运行日期/方式、实际结果位置、逐项人工结论及失败原因。无需新数据库；案例和脱敏结果可用普通文件，检查摘要留在同一轮 PR 或现有 E5 协作记录。日常实验允许未提交 hash，正式版本应可追溯。
5. **修正并回归**：失败先归到输入缺失、Skill 方法、模型数学、格式/集成或 UI 表达边界。不要把所有问题都靠加提示词解决；修正一类问题后复跑相关成对案例，不能只保留最好的一次输出。
6. **形成基线**：正式候选版本在小案例集上没有未解决的明显数学错误、虚构证据或越界结论；足够信息的案例能给针对性分析，缺信息案例能正确收敛。对展示主线和曾失败的代表案例做少量重复运行，记录波动。文案润色可以后续改，不为全措辞组合扩张测试。

人工检查由维护者完成；David 可以独立日常迭代，无需逐次等待批准。Final Gate 由未承担该批实现的复核者检查正式调用证据，并确认实际 UI 没把“可能”隐藏成确定结论。本文只规定质量这一部分，不替代 E5 的事务、超时、失败处理等工程验收，也不替代 E6 部署验收。

进入正式使用需要真实调用、持久化、UI 可见结果和独立复核证据。当前三轮实验只检查隔离环境中的单题调用和内容质量，未发布、未部署、未写入产品数据库；后续真实试验按有界调用计划执行并记录用量。编写 Skill 的 AI 助手所做内容自查，不等于独立 Final Gate。

## 8. 如何持续修改这份设计

### 防止过度设计与样例过拟合

- 每轮先记录失败现象、少量通用修改和停止条件，再运行；优先替换或删除规则，不给具体题目、答案或关键词增加专用分支。
- 保留上一版 Skill 与首次输出，冻结本轮候选后再做新题对照。新题经检查后就成为回归题，不能下一轮仍称作“未见题”。预期答案和评语不传给模型。
- 固定模型、调用配置和输入；旧题改善之外，还检查新题是否退化为“全部 unknown”、过度追问、过长解释、过多训练或新的数学错误。证据充分时仍应敢于指出局部错误。
- 对关键改善做少量重复；同时保留失败输出。小样本只能支持暂时取舍，不声称统计显著、全面准确或已经排除过拟合。同一人设计与检查不是独立盲评。
- 没有明确收益就不升级；明显退化则撤回相关修改或暂不采用候选，不自动追加补丁。连续两轮仍未收敛时，重新检查输入质量、分类语义和目标，而不是无止境加提示词。
- 维持既有五项质量原则和实验脚本，不新增评测服务、数据库、评审 agent 或产品字段。通用检查方法可随证据改进，但每轮有明确调用上限，达到上限就总结。

第三轮后已触发停止连续补丁的条件。用户已确认只推进原题关系解释和有依据的局部发现，拒绝澄清问答/UI 变更；若小范围收尾仍无明显进展，就停止追求单题更深。保留旧实验原始结果，本次只调整设计，没有生成或验证 v0.4。下一阶段重点应回到既定 E5 的上下文、记忆复用与周报综合分析，不以新建复杂聚合系统替代交付。

- **新发现一种失败**：补一个最小案例及禁止断言，能复用已有题目就不增加新材料。
- **只是改善措辞**：改 Skill 和案例检查备注，不必扩写架构文档。
- **修改质量标准、输入边界或分析职责**：同步更新本文，注明理由和受影响案例；涉及产品方向再与用户讨论。
- **更换模型或重要 runtime 配置**：旧结果仍保留，但不当作新组合的质量证明，回放当前小案例集。
- **记录证据**：报告“当前版本在这些案例上的结果”，不把小样本通过率包装成系统整体准确率。未执行保留 `not_collected`。

合成、脱敏案例可版本管理；真实照片、学生身份、私有输入与完整诊断日志不进入公开仓库或 Issue。需要保留真实复现资料时沿用项目私有存储约定，公开记录只放不泄露数据的摘要。开发实验不写入产品学生历史，不混入 `/demo`。

### 接受的限制与 V3 后续方向

- **V2 接受**：只有最终答案时，错因常常无法确定；小案例集不能证明大规模准确率；模型仍可能波动；教材地图有覆盖缺口。
- **行动与反馈的后续方向**：接受记忆不等于执行建议，后续变化不等于建议已生效。完整行动—反馈—调整闭环、基于效果修正记忆，以及有可比作答记录后的稳定趋势提醒，留待 V3 专门讨论，不新增 V2 打卡或反馈 UI。
- **V3 候选**：有足够真实使用证据后扩大评测集、引入教师复核与更细的学科标准；当人工比较成为实际负担时再考虑自动评测辅助；当缺少手写过程成为主要瓶颈时再评估多模态输入；当知识缺口反复影响产品时再评估知识地图扩充。
- **当前不做**：大型 eval 平台、自动裁判作为唯一质量门槛、多 agent 审核流水线、自动扩图或自动进化 Skill。上述方向应与 [V3 延后能力清单](../v3/deferred-capabilities.md)一起用于后续规划，不是 V2 交付依赖。
