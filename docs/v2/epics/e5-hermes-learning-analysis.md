# E5 核心能力设计：从错题分析到学习周报

**状态：Proposed。** 本文记录已确认的 V2 产品设计；设计成立不代表功能已经实现或通过验收。

**读者：** 希望理解系统价值的学生、评审评委，以及负责实现和维护的 David 等开发者。

**Epic：** E5 / [#13](https://github.com/farmerhunter/2026AgentApp/issues/13)。

**设计维护：** Jinghu 与 AI 助手共同梳理，David 可独立实现和迭代，最终质量验收保持独立复核。

**更新：** 2026-08-31。

本文解释两个关键 Skill 背后的思路、策略和取舍，不是提示词全文或逐接口施工说明。运行接入见 [Hermes 运行设计](../hermes-runtime-and-skills.md)，实验与检查方法见 [Finding 质量设计](../hermes-analysis-quality.md)。

## 1. 我们希望帮助学生解决什么

学生知道一道题错了，并不意味着知道为什么错；收集了许多错题，也不意味着知道应该先复习什么。

E5 的核心价值是把这些零散记录变成有依据、可理解、能指导下一步学习的信息：

- **看一道题：** 指出作答中实际存在的问题，解释相关数学关系，给出针对性的帮助。
- **看一段学习过程：** 比较不同题目的证据，识别重复问题和局部变化，确定少量值得优先做的事。

V2 先支持人教版八年级下册数学，重点展示第 16 章二次根式和第 19 章一次函数。目标是中学生可维护的真实能力展示，不是自动判卷平台，也不声称已经证明能提高成绩。

Skill 在这里指可重复执行、可持续改进的一套任务方法。两个关键 Skill 分别承担这两个观察尺度：

| Skill | 学生的问题 | 主要产物 |
| --- | --- | --- |
| `confirmed-mistake-analysis`：已确认错题分析 | 这道题哪里出了问题，下一步怎么改？ | 本题发现、行动建议，以及必要的待确认记忆 |
| `weekly-learning-report`：学习周报 | 这些题之间有什么联系，接下来先做什么？ | 有依据的综合判断、局部变化和复习重点 |

这里的 **finding（学习发现）**，不是一个“粗心”或“概念不清”的标签，而是一段带有作答依据、判断范围和帮助方向的分析。

## 2. 两个 Skill 怎样连起来

```text
练习图片 → OCR 识别题目与作答 → 学生确认错题
                              ↓
                     Skill 1：分析本题
                              ↓
                  保存 finding 与行动建议
                              ├→ 用户接受记忆 → 后续分析可参考
                              ↓
             本周发现＋对应作答＋必要的已接受记忆
                              ↓
                     Skill 2：综合周报
                              ↓
                  学生阅读、打印、选择下一步
```

OCR 负责把图片变成可用信息，学生负责确认哪些题是错题，Hermes 负责分析。E5 不直接解释原图或腾讯云原始响应，也不通过推理重新决定整张试卷哪些题做错。

应用负责准确提供题目、学生作答、已有备注和来源关联；Hermes 负责使用这些信息。照片上有、但 OCR 和应用没有传入的步骤，不能算作模型已经掌握的证据。

### 为什么使用 Hermes，而不是直接发一段提示词

Hermes 承载可修改、可版本管理的分析方法，以及受控的模型调用环境。DeepSeek 是 Hermes 当前使用的模型服务，不是应用绕过 Hermes 单独调用的另一套“智能”。

每次任务使用新会话，但这不等于每次都从零认识学生：应用会从数据库中明确取出允许复用的记忆。连续性来自可追溯的学习记录，而不是某个聊天窗口恰好记得前文。

开发者可以在 Hermes TUI 中快速试验 Skill；产品通过非交互调用执行已知版本。一次任务内部可以完成必要的分析，不需要为了显得智能而拆出许多 Agent、对话轮次或额外服务。更换底层模型时，题目、记忆、分析结果和用户流程的责任边界应保持不变。

教材知识整理还有一个离线辅助 Skill，但它不属于本文讨论的两个在线任务。

## 3. Skill 1：先解释看得见的问题

### 输入与产物

输入是已确认错题的题干、学生作答、已有备注、相关教材节点和必要的已接受记忆。一批分析可以包含多题；每题至多一条主要 finding，不为每个小错误生成一张卡片，也不强求每题产生记忆。

finding 应让学生读懂三件事：看到了什么；这些证据支持怎样的判断、还有什么不能确定；现在可以怎样改。行动建议围绕本题给出，不默认追加澄清问答或新练习。

### 分析策略

1. **先看信息是否足够。** 图示缺失、符号不清或作答残缺时，说明限制，不擅自补题。
2. **核对数学关系。** 检查正确解法和等价表达，避免把不同写法当成错误。如果现有信息与“错题”确认冲突，应提示核对，不硬造错因或自行改写确认记录。
3. **定位有证据的局部问题。** 比较实际步骤，区分观察到的错误与可能的原因。
4. **解释为什么，并给具体帮助。** 深度来自讲清数学关系，而不是堆长解答或推测学生心理。
5. **参考教材与历史。** 用它们定位学习内容、比较此前表现，但不让旧标签覆盖本次作答。

例如，求一次函数表达式时“只求了 k，没有求 b”是可观察的遗漏；“学生认为只要有斜率就能确定直线”则是需要更多证据的假设。可以解释为什么通常需要完整确定两个参数，不能仅凭遗漏就给学生定性。

### 相同错误答案，不一定支持相同错因

以下是人工说明示例，不是 Hermes 实测输出或固定答案模板：

| 输入 | 合适的分析边界 |
| --- | --- |
| 学生写出 `√8＋√2＝√(8＋2)＝√10` | 可以指出这一步错误地把被开方数相加；应先化简为 `2√2＋√2＝3√2` |
| 学生只写出答案 `√10` | 可以解释正确计算，但不能断言学生一定经过了上面那一步；错因可以保留为“不确定” |

“不确定”是合法的分析结果，不是服务失败；但有明确步骤时也不能一律回避判断。正文、分类和界面标签必须表达一致的确定程度。

### 教材地图是参照，不是知识围墙

E3 的知识地图来自教材内容的离线整理与人工检查，帮助系统把问题定位到章节和知识点。它不是学生全部知识的清单，也不是完整的数学知识库。

模型可以分析地图未覆盖的前置知识，不强行挂靠某个节点。若给出知识点 ID，则必须能在指定版本的地图中查到；这保证引用可追溯，**不保证映射或错因判断一定正确**。节点的描述和边界仍需质量检查。模型的一般数学知识也不能冒充教材原文。

## 4. 记忆：保留有用观察，不固定学生标签

记忆连接两次分析，但不是把所有 finding 永久复制一遍。优先保留有实际作答依据、对后续同类学习仍有帮助的观察。

例如可以建议记住：

> 本次求一次函数表达式时，只求出了 k，没有继续确定 b。后续同类题可关注是否完整确定两个参数。

这不等于“学生长期不理解一次函数”或“学生态度不认真”。一次局部错误不能自动变成长期画像。

V2 的规则是：错题分析提出候选，用户接受或拒绝；应用只把已接受的历史记忆带入后续任务。接受代表允许复用，不会把假设变成事实。周报不再产生另一套记忆候选，也不自动编辑、合并或删除旧记忆。

第二次分析仍然以当前证据为准：再出现同类遗漏，可以指出此前也发生过；本次已经正确求出两个参数，就应承认这一步的变化；只有最终答案时，不能因历史记忆而补写学生步骤。

这些记忆记录的是此前的观察，不是永久不变的能力结论。V2 用新的 finding 和周报说明后续变化；更完整的记忆修正和失效机制留待后续设计。

## 5. Skill 2：比较证据，而不是拼接六条分析

### 为什么还需要原题与作答

如果周报只读取前次模型给出的标签，可能把几次猜测总结成一个越来越确定的结论。因此，应用应向周报提供同一学生、同一学科的本自然周 findings，以及对应的已确认题目、作答和已有备注，同时提供已有行动建议、记忆决定、必要的已接受历史记忆和相关教材节点。

题目与 finding 必须准确对应，保留来源和批次关系；不能把两堆互不关联的文字交给模型猜。这里使用已有数据，不要求学生增加输入，也不引入全历史扫描或新的检索服务。

本周 finding 不需要先被接受为记忆才能进入周报；“已接受”限制的是历史记忆复用。拒绝的候选不能当作已接受记忆使用，接受状态也不能充当错因成立的证据。

### 综合策略

1. **说明分析范围。** 根据什么记录得出结论，不能从上传的少量错题推断完整学习表现。
2. **比较实际证据。** 识别不同题目中的相同处理方式，不仅按错误标签计数；同一题重跑不算新的学习证据。
3. **区分重复、变化和不确定。** 多条不确定分析不会因汇总变成确定错因；后面没再上传某类错题，也不能证明已经掌握。
4. **选择重点。** 结合问题的影响、出现的证据和学生可执行的下一步，给出少量复习建议，而不是复述所有题目。

周报可以指出某一步有所改善，即使这道题后续仍有计算错误。它不能因此声称整个知识点已经掌握，更不能在缺少行动反馈时断言“上次建议已经奏效”。

以下是人工示意，仅在作答确实支持时才成立，不是预设模型必须生成的结论：

> 两批练习的已确认错题中，都出现了根式相加时直接合并被开方数的步骤，建议优先复习先化简、再合并同类根式的方法。一次函数题则有局部变化：第二批已经完整确定两个参数，本次错误发生在后续计算，不宜继续归为“遗漏参数”。

它的价值是根据新证据调整判断和复习重点，不是把所有错误都描述得更严重。

### 学生实际看到的成品

目标是一页左右的简短报告，不强制凑字数或每项都给肯定结论：

- **分析范围：** 本周使用了哪些练习和已确认错题。
- **主要问题：** 哪些问题值得优先关注，依据是什么。
- **可见变化：** 哪个步骤有进展；哪些地方仍缺少判断依据。
- **下一步：** 最值得先做的 1–2 件事，尽可能说明怎样观察后续表现。

内容放在现有周报正文中，必要时只补分段排版，不增加页面、图表或操作流程。当前设计分支的真实页面读取 `analysis.overall_summary`；重要结论和建议不能仅存在于页面没有显示的字段中。

周报由用户手工触发，本周没有可用分析数据时不调用模型；再次生成失败时保留上一份成功结果。V2 只保留最新成功版本，不扩展报告历史管理。不同题目之间的综合在这一个周报任务内完成，不另建聚合任务，也不自动改写之前的 findings。

## 6. 用两批仿真练习展示连续性

展示材料需要在设计时准备，不能等功能完成后随便找几道题来凑周报。确定的规模是：**两批、每批 10 题，共 20 题；每批约 3 道重点错题，形成约 6 条 findings，最多接受 2 条记忆。** 这些数量是展示材料规模，不是新增系统配额。

配套 [两批仿真练习文字稿](../../../experiments/hermes-quality/two-batch-learning-fixture/README.md)已准备，包含题目、模拟作答和独立存放的人工参考说明。文字自查不代表已完成图片制作、OCR 或 Hermes 验证。

两份练习覆盖二次根式和一次函数，难度相近，混合选择、填空和少量解答题；有学生作答、适量演算和涂改，排版为识别与切题留足空间。不全部答错，也不直接复制原题。

第一批建立初始观察。第二批用不同题目体现：一次同类问题再次出现；一次此前错误步骤已正确、但后续另有错误的局部改善；一次只有答案、仍不能确定错因的情况。正确题用于还原完整练习，V2 不因此增加自动判分或正确题分析功能。

最终展示走真实的“上传、OCR、确认、Hermes、保存和周报”路径。必须检查实际传入模型的内容；不能用人工理想转写的效果冒充真实 OCR 链路的效果。数学题和参考解答经人工检查，预期结论只用于复核，不传给模型指示它应该说什么。

材料明确标为模拟学生练习，不冒充真实学生一周的使用记录。模拟学习顺序与实际任务运行时间分清楚，可以在准备期间完成，不需要等待一周；周报仍按产品的本自然周规则运行。

保存检查合格的真实生成结果供现场打开和打印；必要时明确切换到独立的 `/demo`，不在真实链路中偷偷替换预制答案。仿真演示说明系统怎样工作，不能作为真实学习改善或整体准确率的证明。

## 7. 怎样判断两个 Skill 真正有用

质量检查分为两件事：程序验证结果能否安全使用，人检查分析是否值得学生相信。

程序检查结构、数量、题目关联和引用是否合法；无效结果或调用失败不得留下半份业务数据。人工对照实际输入，检查数学正确、忠于证据、判断范围、建议可执行和教材映射是否合适。模型返回合法 JSON、自报高置信度或自评通过，都不能代替内容检查。

单题重点检查“有步骤”和“只有答案”是否被区别对待。累积分析重点检查历史记忆是否帮助比较、是否反而造成先入为主，以及重复问题和局部改善能否同时被正确表达。展示材料应支持这些现象，普通输入没有相应证据时不强行凑齐。

迭代采用小案例、少量通用修改和有界回放：保留原始失败输出、输入和 Skill 版本，检查旧题之外的变体。没有明显收益就不继续堆规则，不追求对某几道题的固定措辞。小样本上的改善不能宣传成普遍可靠性。

现有三轮单题实验已经暴露出仅凭答案过度归因、数学推广不当和补写学生步骤等问题；两个修订候选没有整体采用。它们用于识别风险，不是正式 Skill 已合格的证明。两批数据的记忆复用、周报综合、真实保存与展示仍需实现和独立验收。具体记录见 [质量设计与实验链接](../hermes-analysis-quality.md)。

## 8. 已确认的取舍与未来方向

V2 保留五条核心边界：分析必须有证据；教材引用可追溯但不限制数学知识范围；历史记忆经用户接受且不能覆盖当前作答；周报综合与记忆维护分开；结果真实可保存、失败不混入静态替代品。

这些边界让有限的系统复杂度集中在学习分析质量上。接受的限制包括：只有最终答案时错因可能无法确定；教材地图存在覆盖缺口；模型会波动；仅收集错题无法建立完整的学习趋势。V2 不增加澄清问答、自动判卷、复杂学习计划、独立记忆整理服务或大型评测平台。

### 未来的行动与反馈闭环

用户提出的 RDCA 方向，在本文中指需要后续专门设计的学习闭环，而不是声称已实现某套既定方法：学习证据形成见解，学生选择并执行行动，系统收到新作答或执行反馈，再修正判断与下一步帮助。

接受记忆不等于执行行动，执行行动不等于产生效果。完整闭环需要知道“这次作答在检验哪条建议”，也需要允许反馈否定原先的分析。届时记忆应能记录哪些帮助有效、哪些旧判断已经失效，而不只是记录学生的问题。

V2 只要求建议具体，并在后续已有作答中观察可见变化；不新增行动打卡或反馈界面，不把周报中的“下周行动”当成已执行任务。完整闭环及相关记忆更新属于后续设计方向，不预先冻结 API、状态机或实现排期。

稳定趋势与异常提醒同样需要更完整、可比较的记录，包括作答总量、难度、此前表现，最好同时包含正确与错误作答。只有错题增多，不能推断学生状态下降或态度不认真。条件具备后先描述表现变化，再给温和的检查建议。

上述方向已纳入 [V3 延后能力清单](../../v3/deferred-capabilities.md)，用于后续规划，不是 E5 的新增交付条件。

## 9. 给 David 与评委的阅读提示

对开发者：本文是产品行为和质量取舍的依据，不冻结新的接口字段。优先维护题目—finding—记忆—报告的来源关系；让页面实际显示关键结论；区分建议、接受记忆与执行反馈。具体上下文筛选、接口兼容、运行配置和开发顺序还需在 E5 实现设计中落实，不能把本文示例硬编码成结果。

对评委：可以沿一条结论反向查看它来自哪道题、哪一步作答，观察系统是否承认证据不足、是否利用后续记录调整判断，以及建议是否具体。这比只看报告篇幅或漂亮标签，更接近本系统希望展示的价值。
