# 给 David 的 V2 一页开发说明

V2 要做的事可以用一句话说清：

> 在 VPS 上保留一个永远能演示的静态版，同时做出一条真实链路：上传数学练习图片，识别题目和学生作答，学生勾出错题，Hermes 给出学习分析和记忆建议，最后生成周报。

## 先记住这五件事

1. `/demo` 是 V1 静态兜底，冻结它，不接 API。
2. `/app` 是真实版，只走 API；出错就明确显示错误，不能偷偷读静态数据。
3. OCR 负责“看见题目和作答”，学生负责“确认哪题错”，Hermes 负责“分析为什么错、以后怎么学”。
4. SQLite 保存产品数据和已接受记忆；不要依赖 Hermes 自己记住了什么。
5. V2 追求能稳定展示，不追求生产级大而全。

## 按什么顺序做

- E1 已完成：不要重做数据库/API 基础。
- E2：先把 `/demo`、`/app` 和四页真实 UI 骨架稳定下来。
- E3：准备一份数学教材知识地图 JSON。
- E4：接真实图片上传和腾讯 QuestionSplitOCR，让用户勾选错题。
- E5：接 Hermes CLI，迭代三个 Skill，保存分析、记忆决定和周报。
- E6：部署到 VPS，做两次完整实测和终评演练。

E2、E3、E4 可以并行推进；E5 依赖 E3/E4 的可靠输入；E6 最后把所有模块接起来。

## 最小产品规则

- 一科：数学；一本教材：人教版八年级下册。
- 一次一张 JPG/PNG，不超过 10 MB；一批最多 10 题。
- 原图只放 VPS 私有目录；前端用 bbox 显示题目区域，不保存裁图。
- 用户只需勾错题；OCR 漏掉作答时才补文字。
- 一次确认批次对应一次 Hermes 分析。
- 记忆只能接受或拒绝；周报手工触发，只保留最新成功版本。
- 展示数据控制在约 6 题、2 个知识区域、最多 2 条已接受记忆。

## Hermes 怎么接

应用不能直接调 DeepSeek，也不能用 tmux 模拟人敲 TUI。应用启动非交互 Hermes CLI，通过 JSON stdin/stdout 交换数据。TUI 是你试验和改 Skill 的实验室。

Skill 推荐流程：

```text
在 studyv2-lab TUI 快速试 -> 小样例回放 -> 用 CLI 跑同样输入
-> 通过 contract -> 提交 Skill，记录 content hash -> runtime 使用
```

详细规则见 [Hermes 运行与 Skill 设计](hermes-runtime-and-skills.md)。

## 做到什么就算 V2 MVP

- `/demo` 独立可用。
- `/app` 真实完成一次“上传 -> OCR -> 勾错题 -> Hermes -> 保存”。
- 一份真实周报已生成、保存、能稳定打开和打印。
- 服务失败不会留下半份结果，公开页面没有密钥和真实学生资料。

如果实现想明显超出这些边界，先查 [V3 延后能力清单](../v3/deferred-capabilities.md)。只在隐私、费用、权限、不可逆迁移或产品方向变化时找产品负责人确认；普通低风险实现由你自主决定。
