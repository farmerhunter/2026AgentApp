**状态：Current / Living document。** 本文只规定 Epic 成果、依赖和总体验收；每个 Epic 启动时再设计内部 issue。

## 2. E1–E6 成果

### E1：持久化学习数据 API（#63，Done）

SQLite 与 REST API 基础已经完成。E1 不再扩大范围；后续 Epic 可以在其上做最小 schema/API 扩展，并保持兼容与迁移说明。

### E2：双线入口与稳定真实工作台（#68）

建立隔离的 `/demo` 与 `/app`，尽早冻结 `/app` 四页 UI 骨架和 loading/empty/failed/saved 状态。`/app` 只走 API，不做静态 fallback。

### E3：教材知识底图与扩展边界（#87）

离线处理人教版八年级下册数学 PDF，形成仓库版本化、只读、可引用的知识地图。只做一科，但数据结构保留学科、教材和版本边界。

### E4：练习/试卷图片导入与错题确认（#88）

实现真实 JPG/PNG 上传、腾讯 QuestionSplitOCR、题干和学生作答展示、bbox 区域查看与人工勾选错题。V2 不自动判错。

### E5：Hermes 分析、记忆与周报（#13）

用错题分析和周报两个在线 Skill 跑通学习分析；教材整理 Skill 是离线辅助。Findings/actions 校验后自动保存；memory candidate 由错题分析提出、用户接受或拒绝；只有已接受的历史记忆会进入下一次上下文。周报综合本周 findings 和对应作答，不再产生记忆候选。产品价值与设计取舍见 [E5 核心能力设计](epics/e5-hermes-learning-analysis.md)。

开发方式：确定性 API/SQLite/校验逻辑在本地开发；真实 Hermes 调用和 Skill 迭代在 VPS 独立开发目录和数据库验证，不触碰生产数据。详见 [Hermes 设计](hermes-runtime-and-skills.md)。

### E6：VPS 双线部署与端到端验收（#69）

用 Nginx + systemd 提供 `/demo`、`/app`、API 和私有运行目录；在 VPS 上至少两次跑通真实链路并验证重启、失败、恢复与隐私边界。

## 3. R1：终评风险约束（叠加在 E1–E6 之上）

R1 不改变产品架构，也不把 Epic 粗化。它只规定交付优先级：

- 从本次重基线批准起 48 小时内冻结一致 UI 骨架：本周概览、导入与确认、分析与记忆、周报与打印；之后只补状态和真实数据，不随意改主流程。
- P0 真实路径：上传 -> OCR -> 勾选错题 -> Hermes -> 保存和展示。
- 记忆和周报至少真实成功运行一次并保存；终评现场不强求每一步都重新在线生成。
- 四层兜底：PPT、`/demo`、`/app` 已保存真实结果、60–90 秒真实端到端录屏。
- PPT、live demo、易拉宝、视频和系统页面使用同一个学生故事、同一份展示数据和一致截图。
- 建议节奏：终评前 7 天在 VPS 连续跑通两次；前 4 天锁定成功周报和展示数据；前 2 天冻结代码与现场脚本。

## 4. MVP 验收门槛

- `/demo` 可独立完成 V1 流程，断开 API/Hermes 仍可用。
- `/app` 能真实保存一张图片的 OCR、错题确认、Hermes 分析和记忆决定。
- 至少一份真实生成并保存的周报能稳定打开和浏览器打印。
- 外部服务失败不产生半份领域数据。
- 展示环境不含密钥、真实学生隐私或公开可访问的原图。
- David 能仅根据 [一页开发说明](development-guide.md) 找到下一步、边界和验收方式。
